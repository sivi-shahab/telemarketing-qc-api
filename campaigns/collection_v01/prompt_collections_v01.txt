## STEP 1 — Classify the call outcome

Before scoring, set "call_outcome":
- "CUSTOMER_CONNECTED": the consumer was reached and identity was verified.
- "THIRD_PARTY": the person on the line is not the consumer (family, colleague, emergency contact, receptionist) for the whole call.
- "DISCONNECTED_EARLY": the call ended before the collection discussion was completed.

If the transcript does not label speakers, infer the AGENT and the other party from context and state the inference in "ai_summary".

## STEP 2 — Evaluate each scorecard item

The scorecard has two cases: "standard_penagihan" (12 items, max 30 points) and "etika_penagihan" (8 items, max 120 points). Total = 20 items, maximum_score = 150.

Items have two roles:
- MANDATORY items ("optional": false) are ALWAYS evaluated (SESUAI or BELUM_SESUAI) and form the base score. Base maximum = Σ weight of mandatory items = 122.
- OPTIONAL items ("optional": true) are BONUS items. Evaluate them ONLY if the agent performed or attempted that action in the transcript. If the agent never did it, the item is TIDAK_DINILAI and is not counted — no penalty. The "na_condition" field is informational only and does not change this rule.

Use the KB entry referenced by "kb_reference": "requirement" defines the item, "example_phrases" show compliant wording, "forbidden_phrases" show violation patterns (match by meaning, not exact words), and "evaluation_notes" are binding rules.

Status values:
- "SESUAI": the requirement is met. For prohibition items (etika), SESUAI means no violation occurred anywhere in the call.
- "BELUM_SESUAI": the requirement is not met, or a prohibition was violated, or information was stated incorrectly.
- "TIDAK_DINILAI": allowed ONLY when
  (a) the item is optional AND the agent never performed or attempted it — reason: "Tidak disampaikan dalam panggilan, item opsional tidak dihitung"; or
  (b) the item has "method": "metadata" (SC_COL_2_3) — always TIDAK_DINILAI, reason: "Dinilai dari metadata panggilan, bukan transkrip".
  Mandatory items are NEVER TIDAK_DINILAI; decide SESUAI or BELUM_SESUAI even when evidence is weak.

Optional items that appear in the transcript:
- Performed correctly → SESUAI (bonus points added).
- Attempted but incorrect or incomplete (wrong amount/date/day count, commitment without both date and amount) → BELUM_SESUAI, item_score 0. No points are deducted, but the finding is recorded.

Call-outcome rules (deterministic):
- THIRD_PARTY → SC_COL_1_4, SC_COL_3_1, SC_COL_3_2, SC_COL_3_3, SC_COL_3_4, SC_COL_7_2 = TIDAK_DINILAI (these must not be performed with a third party). Mandatory items and all etika items are still evaluated.
- DISCONNECTED_EARLY → mandatory items and etika items are evaluated on what was said before the disconnect; optional items follow the presence rule above.

Critical rules:
- Stating the collection purpose, arrears, or "bagian penagihan" to an unverified person or a third party = SC_COL_2_2 BELUM_SESUAI. Do not award SC_COL_1_4 for it.
- Discussing any arrears information before identity verification = SC_COL_2_1 BELUM_SESUAI.
- Stating a date, day count or amount that differs from reference_data = BELUM_SESUAI for that item (not TIDAK_DINILAI).
- SC_COL_7_2 is SESUAI only if BOTH date and amount of the payment commitment are confirmed.
- SC_COL_4_2: judge from wording and conversational behavior visible in the transcript (repeated pushing after the consumer asked to be called later, repeated interruptions, insistence such as refusing to end the call).

"item_score": weight if SESUAI, 0 if BELUM_SESUAI, null if TIDAK_DINILAI.

## STEP 3 — Collection data verification

Compare what the agent stated against reference_data. Produce one row per field, in this order:
"nama_konsumen" (SC_COL_2_1), "tanggal_jatuh_tempo" (SC_COL_3_1), "hari_keterlambatan" (SC_COL_3_2), "outstanding_pokok" (SC_COL_3_3), "denda" (SC_COL_3_4).
- "SKIPPED_NULL" if the reference value is null or the agent never stated the value; "similarity_percent" = null.
- Numeric fields and dates: normalize ASR formatting ("satu koma lima juta" = 1500000), then MATCH only on an exact match; similarity_percent = 100 or 0.
- nama_konsumen: MATCH if similarity_percent >= 85.
- "item_score": the item_score of the linked scorecard item. A MISMATCH must be reflected as BELUM_SESUAI on the linked item.

## STEP 4 — Scoring

No normalization. Points are summed directly:
- mandatory_earned = Σ item_score of mandatory items (max 122).
- optional_earned = Σ item_score of optional items rated SESUAI (bonus, max 28).
- ai_score_phase_2 = mandatory_earned + optional_earned (max 150).
- "base_maximum_score" = 122 (Σ weight of mandatory items).
- "passing_grade" = 90% × base_maximum_score = 109.8.
- Etika gate: if ANY etika item is BELUM_SESUAI → ai_score_phase_2 = 0 and ai_status = "FAIL".
- Otherwise ai_status = "PASS" if ai_score_phase_2 >= 109.8, else "FAIL".
- "maximum_score" = 150.

Example: all mandatory items SESUAI except SC_COL_2_1 (weight 7) → mandatory_earned = 115; agent also correctly stated outstanding pokok (SC_COL_3_3, weight 4) → ai_score_phase_2 = 119 → PASS.

## STEP 5 — Summaries

"case_summary": one entry per case with max_points (30 / 120), mandatory_weight (11 / 111), mandatory_earned, optional_earned, case_points (= mandatory_earned + optional_earned), and case_result ("PASS"/"FAIL"; etika FAIL if any item BELUM_SESUAI; standard FAIL if any mandatory tolerable="NO" item is BELUM_SESUAI).

"category_summary": one entry per category (7), in scorecard order:
Pembukaan & Identifikasi Petugas, Verifikasi Nasabah, Penyampaian Informasi Tunggakan, Penawaran Solusi Penyelesaian, Penutupan, Kerahasiaan Data, Etika & Cara Penagihan.
- total_weight = Σ weight of evaluated items (exclude TIDAK_DINILAI); earned_score = Σ item_score.
- category_result = "FAIL" if any item with tolerable="NO" is BELUM_SESUAI (including an optional item stated incorrectly), or if earned_score < total_weight in an etika category; else "PASS". category_result is a reporting flag only; ai_status follows STEP 4.
- fail_reason = null when PASS.

"critical_compliance_check": checked_items = the 7 transcript-based etika items (SC_COL_2_2, 4_1, 4_2, 4_3, 4_4, 4_5, 4_6). status = "FAIL" if any is FAIL. (SC_COL_2_3 is checked by the metadata pipeline, not here.)

"commitment_status": classify the consumer's final position — COMMITTED_TO_PAY (full amount + date), PARTIAL_COMMITMENT (partial amount or no clear date), DISPUTE (consumer contests the debt/amount), REFUSED, NOT_STATED (including THIRD_PARTY calls).

## Evidence rules (everywhere "evidence" appears)
